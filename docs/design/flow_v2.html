鸣潮启动器 · 完整逻辑

左侧为主线步骤，右侧为该步骤的分支结果

主流程

01打开 App
界面立即出现，不修改任何系统设置
02申请 Shizuku 授权
只申请，不改设置
已授权 → 分辨率、密度、三键导航全部可用
未授权 → 跳过分辨率与导航
方向控制仍正常工作
03选择屏幕分辨率
原生 · 高清 · 最大渲染极限
原生 1080p → 不改分辨率，只锁方向
高清 屏幕物理分辨率 → 直接选中
最大渲染极限 → 进入测试子流程
见下方「渲染档测试」
未选择 → 启动按钮灰显，不可点击
04点「启动游戏」
选定分辨率后按钮才变为主色
05挂方向控制悬浮窗
1×1 透明窗口置于最上层
决定全屏方向，压住游戏自带的方向声明
挂载成功 → 继续下一步
失败自动重试 3 次
3 次全失败 → 弹窗「重试 / 取消」
游戏不启动，屏幕未做任何改动
06改分辨率 + 密度 + 导航
仅 Shizuku 已授权时执行
密度按相同倍数变化，界面元素大小不变
原生档 → 跳过尺寸，仅设方向
高倍率档 → 强制切换三键导航
高分辨率下全面屏手势区域失效
未授权 → 本步整体跳过，日志注明
07拉起鸣潮
悬浮窗就位、设置生效后才启动
08退出还原
移除悬浮窗 · 恢复分辨率、密度、导航
按进入前的快照还原，非固定默认值
点「还原显示」 → 立即还原
从最近任务划掉 → 前台服务自动还原
进程被系统杀死 → 下次打开自动补还原

渲染档测试（选「最大渲染极限」后进入）

T1展开四档
1.4× / 1.6× / 1.8× / 2.0×
按屏幕物理分辨率与密度实时计算
1.4× → 稳妥
1.6× → 有风险
1.8× → 风险高
2.0× → 极易崩溃
T2点选一档 → 进入测试
立即应用该分辨率，开始 10 秒倒计时
测试目的：确认该分辨率下触摸是否正常
T310 秒测试中
全屏遮罩 · 圆环倒计时
屏幕显示滑动轨迹（长度短于屏宽，不遮挡内容）
滑动屏幕 → 显示轨迹，判断是否跟手
点「确认无误」 → 弹二次确认
什么都不做 → 10 秒后自动结束
T4二次确认
说明所选档位与风险提示
确认无误 → 提前结束测试
继续测满 10 秒 → 回到倒计时
T5结束测试 → 还原屏幕
无论通过或超时，都会先恢复到进入测试前的状态
T6标记并选定
通过的档位显示「✓ 可用」并自动选中
启动按钮由灰变为主色
回到主流程 04：等待点击「启动游戏」
用户操作 程序执行 完成 / 还原 失败分支
